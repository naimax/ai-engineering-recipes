# Вариации charter под тип процесса

Одна нотация ([`notation.md`](notation.md)), разные классы работ. Выберите шаблон, дополните промптом 1 из [`prompts.md`](prompts.md).

Цель: показать, как один принцип (роль + tools + Never) раскрывается на разных процессах, не копировать готовый charter.

## Когда workflow, когда agent

| Ситуация | Лучше workflow (фиксированный код / чеклист) | Лучше agent (charter) |
|----------|-----------------------------------------------|------------------------|
| Шаги всегда одни и те же | CI job, lint, format | нет |
| Следующий шаг зависит от вывода tool | нет | исследование бага, миграция с откатом |
| Риск необратимого | human gate в коде | Never + deny на tool |
| Нужен только текст совета | чат | нет |
| Нужен артефакт на диске | нет | rename, patch, отчёт |

Источник границы: [Anthropic building effective agents](https://www.anthropic.com/engineering/building-effective-agents).

## Шаблоны A–D

### Вариация A: пакетная работа на файлах

Процесс: массовое однотипное действие (rename, замена строки, перенос по маске).

| Поле charter | Пример заполнения |
|--------------|-------------------|
| Роль | «Переименовывает файлы в одной папке по маске» |
| Tools | Read, Glob, Edit, без Shell rm |
| Never | удаление; правки вне `<папка>`; force git |
| Успех | `ls` / tree: N файлов с новым префиксом; diff в trace |
| Против чего | план в абзаце, 0 Edit в trace |

Польза: человек задаёт маску один раз; агент идёт по файлам; вы проверяете diff, не переписку.

### Вариация B: исполнитель (implementer)

Процесс: одна фича/фикс с проверкой на диске.

| Поле charter | Пример |
|--------------|--------|
| Роль | «Чинит баг в модуле X по описанию в issue» |
| Tools | Read, Edit, Shell (тесты только allowlist команд) |
| Never | deploy; push; само «готово» без вывода команды |
| Успех | конкретная команда теста + exit 0 в trace |
| Против чего | «всё работает» без stdout |

Польза: LLM не заменяет ревью: отделяете implementer charter от checker (вариация C).

### Вариация C: проверяющий (checker only)

Процесс: вердикт по уже сделанному (PR, черновик, diff).

| Поле charter | Пример |
|--------------|--------|
| Роль | «Ревьюер: только PASS/FAIL с цитатами» |
| Tools | Read, Grep, Shell read-only, нет Edit |
| Never | править файлы; PASS без evidence; смешивать с автором |
| Успех | файл `review.md` с PASS/FAIL + 3–7 путей/цитат |
| Против чего | «выглядит ок» без ссылок на строки |

Польза: закрывает `common/README` §1: исполнитель не судья. Новый чат / другая роль в charter.

Связка: рецепт `many-agents/` развернёт multi-agent; здесь минимум двух charter на одну задачу.

### Вариация D: read-only исследование

Процесс: ответ «где и почему» без правок репо.

| Поле charter | Пример |
|--------------|--------|
| Роль | «Исследователь: находит причину в логах и коде» |
| Tools | Read, Grep, search, без Edit/Shell destructive |
| Never | любая правка; выдуманный путь файла |
| Успех | отчёт с ≥3 цитатами path:line из repo |
| Против чего | общие рассуждения без grep |

Польза: agent loop с ground truth из repo, но bounded autonomy: не трогает прод.

## Как выбрать вариацию

1. Опишите артефакт на выходе (файлы, отчёт, вердикт).
2. Если артефакт только текст без side effect: скорее чат или вариация D.
3. Если side effect: charter A/B + checker C на той же задаче.
4. Прогон промпта 2 из `prompts.md` на одной реальной задаче; FAIL по §«Чат vs агент»: правка charter, не переписывание промпта.
